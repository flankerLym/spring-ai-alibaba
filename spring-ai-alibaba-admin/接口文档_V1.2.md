# Spring AI Alibaba Admin 开放 API 文档 v1.2

## 1. 接入说明

- **Base URL**：`http(s)://{host}`（以实际部署地址为准）
- **认证**：所有 `/api/v1/**` 接口均须携带 `Authorization: Bearer <API_KEY>`
- **请求**：`Content-Type: application/json`；所有下列接口均为 `POST`
- **外部用户**：Workflow 请求可传 `userId`（第三方业务用户标识，**不超过 32 个字符**）；建议每次调用传入，便于会话和 Trace 关联。它**不是** `appId`，当前代码允许不传。
- **会话**：首次调用 `conversationId` 可留空；后续多轮交互传回上次得到的 ID。
- **发布版本**：调用应用时使用 `draft: false`；调用方无需传 `company_name`，该信息由 API Key 关联配置确定。

| 功能 | 路径                                        |
|---|-------------------------------------------|
| 查询应用 | `/api/v1/apps`                            |
| Workflow 同步/流式调用 | `/api/v1/apps/workflow/completions`       |
| Workflow 异步启动 | `/api/v1/apps/workflow/async-completions` |
| Workflow 异步查询 | `/api/v1/apps/workflow/async-results`     |
| Workflow 停止 | `/api/v1/apps/workflow/stop-completions`  |
| 会话列表查询 | `/api/v1/conversations/query`             |
| 会话消息详情查询 | `/api/v1/conversations/messages/query`    |

## 2. 查询应用

`POST /api/v1/apps`

```json
{"type":"workflow","status":"published","pageNum":1,"pageSize":20}
```

| 请求字段 | 规则 |
|---|---|
| `appId` | 可选，精确匹配 |
| `name` | 可选，名称模糊匹配 |
| `type` | 建议填写 `workflow`，只查询工作流应用 |
| `status` | 可选，`draft` / `published` / `published_editing` |
| `pageNum` / `pageSize` | 默认 `1` / `20`；`pageSize` 最大 `100` |

**必须至少填写** `appId`、`name`、`type`、`status` 中的一项。

**返回示例（精简展示）：**

```json
{
  "requestId": "req_xxx",
  "code": 200,
  "message": "success",
  "data": {
    "pageNum": 1,
    "pageSize": 20,
    "total": 1,
    "records": [{
      "appId": "app_xxx",
      "name": "示例工作流",
      "type": "workflow",
      "status": "published",
      "publishedVersion": "3",
      "api": "/api/v1/apps/workflow/completions",
      "asyncApi": "/api/v1/apps/workflow/async-completions",
      "inputSchema": [
        {"key":"query","type":"String","required":false,"source":"sys"},
        {"key":"order_no","type":"String","required":true,"source":"user"}
      ],
      "requestJson": {"appId":"app_xxx","conversationId":"","stream":false,"draft":false,
        "inputParams":[
          {"key":"query","type":"String","source":"sys","value":"请输入用户问题"},
          {"key":"order_no","type":"String","source":"user","value":""}
        ]}
    }]
  }
}
```

- `inputSchema`：业务输入参数定义；`requestJson`：服务端生成的请求模板（上例仅展示结构）。**实际调用请以返回的完整 `requestJson` 和 `inputSchema` 为准。**
- 仅对有已发布版本的应用提供可用的调用配置；如果未找到已发布配置，可能返回 `schemaError`。
- 其他可能返回描述、图标、创建/修改时间、认证方式等字段，不影响基本联调。

## 3. Workflow 同步 / 流式调用

`POST /api/v1/apps/workflow/completions`

```json
{
  "appId": "app_xxx",
  "userId": "user_001",
  "conversationId": "",
  "stream": false,
  "draft": false,
  "inputParams": [
    {"key":"query","type":"String","source":"sys","value":"查询订单"},
    {"key":"order_no","type":"String","source":"user","value":"NO123"}
  ]
}
```

| 字段 | 说明 |
|---|---|
| `appId` | 必填，工作流应用 ID |
| `userId` | 可选，第三方用户 ID，最长 32 字符；建议传入 |
| `conversationId` | 可选，空值时服务端生成 |
| `stream` | 可选，默认 `false`；为 `true` 时使用 SSE |
| `draft` | 可选，外部使用已发布版本时传 `false` |
| `inputParams` | 工作流输入参数列表；按第 2 节返回的 `inputSchema` 填写 |

`inputParams[]` 包含 `key`（原始变量名）、`type`、`source`（`sys` 或 `user`）、`value`。通常 `query` 使用 `sys`，Start 节点自定义输入使用 `user`；**变量名保持原样**，不强制改成驼峰。

**非流式响应（业务对象）：**

```json
{
  "conversationId": "conv_xxx",
  "taskId": "task_xxx",
  "status": "completed",
  "content": "{\"result\":\"PASS\"}"
}
```

`status` 可能为 `in_progress`、`completed`、`failed`、`pause`；失败时可包含 `errorCode`、`errorMessage`。

**SSE**：将上述请求的 `stream` 改为 `true`，响应头为 `text/event-stream`。每条事件形如：

```text
data: {"conversationId":"conv_xxx","taskId":"task_xxx","status":"in_progress","content":"处理中"}

data: {"conversationId":"conv_xxx","taskId":"task_xxx","status":"completed","content":"完成"}
```

按 `status` 判断业务状态；不要依赖 OpenAI 式的 `[DONE]` 标记。

## 4. Workflow 异步调用

异步接口的部分字段**仍使用 `snake_case`**，与上述同步接口不同；以下名称严格对应当前代码。

### 4.1 启动

`POST /api/v1/apps/workflow/async-completions`

请求体使用第 3 节的 Workflow 请求格式（可不传 `stream`）。成功时：

```json
{
  "code": 200,
  "message": "success",
  "data": {"task_id":"task_xxx","conversation_id":"conv_xxx","request_id":"req_xxx"}
}
```

保存 `data.task_id`，用于异步查询或停止任务。

### 4.2 查询结果

`POST /api/v1/apps/workflow/async-results`

```json
{"task_id":"task_xxx"}
```

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "task_id": "task_xxx",
    "conversation_id": "conv_xxx",
    "task_status": "success",
    "task_exec_time": "1280ms",
    "outputs": [{"node_id":"node_end_1","node_name":"结束","node_type":"End","node_status":"success","content":"{\"result\":\"PASS\"}"}]
  }
}
```

- 查询请求和响应中的任务标识均为 **`task_id`**；不要写成 `taskId`。
- `outputs` 仅包含执行经过的 Output / End 节点；失败时还可能返回 `error_code`、`error_info`。

### 4.3 停止任务

`POST /api/v1/apps/workflow/stop-completions`

```json
{"task_id":"task_xxx"}
```

```json
{"code":200,"message":"success","data":true}
```

注意：停止请求明确使用 **`task_id`**（不是 `taskId`）；`data` 表示停止操作的布尔结果。

## 5. 会话列表查询

`POST /api/v1/conversations/query`

查询当前 API Key **有权访问且属于其工作空间**的历史会话，支持多条件组合筛选、分页和排序。所有筛选条件均可选；不传筛选条件时返回授权范围内的会话列表（仍按页返回）。

**最简测试请求：**

```json
{"pageNum":1,"pageSize":10}
```

**多条件请求示例：**

```json
{
  "appId": "10001",
  "userId": "student_001",
  "invokeSource": "湖南大学",
  "name": "咨询",
  "status": "normal",
  "startTime": "2026-10-01T00:00:00+08:00",
  "endTime": "2026-10-09T23:59:59+08:00",
  "minMessageCount": 2,
  "maxMessageCount": 100,
  "sortBy": "updatedAt",
  "sortOrder": "desc",
  "pageNum": 1,
  "pageSize": 20
}
```

| 请求字段 | 规则 |
|---|---|
| `appId` | 可选，单个应用 ID，精确匹配 |
| `appIds` | 可选，应用 ID 数组，如 `["10001","10002"]`；可与 `appId` 同时传入，按并集筛选 |
| `conversationId` | 可选，会话 ID，精确匹配 |
| `userId` | 可选，第三方业务用户 ID，精确匹配 |
| `invokeSource` | 可选，调用来源/企业名称，精确匹配 |
| `name` | 可选，会话名称，模糊匹配 |
| `status` | 可选，会话状态，精确匹配，如 `normal` |
| `startTime` / `endTime` | 可选，**会话创建时间 `created_at`** 的闭区间筛选，允许只传一端 |
| `minMessageCount` / `maxMessageCount` | 可选，会话消息数量下限 / 上限（含边界）；必须非负且下限不大于上限 |
| `sortBy` | 可选，`createdAt` / `updatedAt` / `messageCount`；默认 `updatedAt` |
| `sortOrder` | 可选，`asc` / `desc`；默认 `desc` |
| `pageNum` / `pageSize` | 可选，默认 `1` / `20`；`pageNum ≥ 1`，`1 ≤ pageSize ≤ 100` |

- `appId`、`appIds`、`conversationId` 对应当前会话存储中的 **正整数 BIGINT ID**，请传字符串形式的数字，如 `"10001"`；不要使用 `"app_xxx"`、`"conv_xxx"` 作为实际查询值。
- 如果请求指定了不在当前 API Key 工作空间或授权范围中的 `appId`，接口返回 **403**；不会扩大查询权限。
- 时间参数建议使用带时区的 ISO-8601，例如 `2026-10-09T10:00:00+08:00`，也接受 `Z`、不带时区的 `yyyy-MM-dd'T'HH:mm:ss` 或 `yyyy-MM-dd HH:mm:ss`；未带时区时按服务端默认时区处理。

**返回示例：**

```json
{
  "requestId": "req_xxx",
  "code": 200,
  "message": "success",
  "data": {
    "current": 1,
    "size": 20,
    "total": 1,
    "records": [
      {
        "conversationId": "123456789",
        "appId": "10001",
        "userId": "student_001",
        "invokeSource": "湖南大学",
        "name": "咨询",
        "status": "normal",
        "messageCount": 8,
        "createdAt": "2026-10-09T02:00:00.000+00:00",
        "updatedAt": "2026-10-09T02:15:00.000+00:00"
      }
    ]
  }
}
```

注意：列表返回的分页字段是 **`current` / `size` / `total` / `records`**，不是请求中的 `pageNum` / `pageSize`。时间字段的具体时区与格式以实际服务序列化配置为准。

## 6. 会话消息详情查询

`POST /api/v1/conversations/messages/query`

根据 `conversationId` 返回**会话基本信息**以及该会话的**分页历史消息**，消息可按角色、状态、创建时间筛选，并按会话内顺序正序或倒序排列。

**最简测试请求：**

```json
{"conversationId":"123456789","pageNum":1,"pageSize":20}
```

**筛选请求示例：**

```json
{
  "conversationId": "123456789",
  "role": "user",
  "status": "success",
  "startTime": "2026-10-01T00:00:00+08:00",
  "endTime": "2026-10-09T23:59:59+08:00",
  "sortOrder": "asc",
  "pageNum": 1,
  "pageSize": 20
}
```

| 请求字段 | 规则 |
|---|---|
| `conversationId` | **必填**，会话 ID（正整数 BIGINT 字符串），精确匹配 |
| `role` | 可选，消息角色，精确匹配，常见为 `user` / `assistant`；不传则不过滤 |
| `status` | 可选，消息状态，精确匹配，如 `success` |
| `startTime` / `endTime` | 可选，**消息创建时间 `created_at`** 的闭区间筛选 |
| `sortOrder` | 可选，`asc` / `desc`，默认 `asc`；按 `sequence`、`messageId` 排序 |
| `pageNum` / `pageSize` | 可选，默认 `1` / `20`；`pageNum ≥ 1`，`1 ≤ pageSize ≤ 100` |

**返回示例：**

```json
{
  "requestId": "req_xxx",
  "code": 200,
  "message": "success",
  "data": {
    "conversation": {
      "conversationId": "123456789",
      "appId": "10001",
      "userId": "student_001",
      "invokeSource": "湖南大学",
      "name": "咨询",
      "status": "normal",
      "messageCount": 8,
      "createdAt": "2026-10-09T02:00:00.000+00:00",
      "updatedAt": "2026-10-09T02:15:00.000+00:00"
    },
    "messages": {
      "current": 1,
      "size": 20,
      "total": 2,
      "records": [
        {
          "messageId": "1111",
          "parentMessageId": null,
          "sequence": 1,
          "role": "user",
          "content": "你好",
          "contentType": "text",
          "requestId": "req_001",
          "traceId": "trace_001",
          "userId": "student_001",
          "status": "success",
          "createdAt": "2026-10-09T02:00:00.000+00:00",
          "updatedAt": "2026-10-09T02:00:00.000+00:00"
        },
        {
          "messageId": "1112",
          "parentMessageId": "1111",
          "sequence": 2,
          "role": "assistant",
          "content": "你好，有什么可以帮你？",
          "contentType": "text",
          "requestId": "req_001",
          "traceId": "trace_001",
          "userId": "student_001",
          "status": "success",
          "createdAt": "2026-10-09T02:00:05.000+00:00",
          "updatedAt": "2026-10-09T02:00:05.000+00:00"
        }
      ]
    }
  }
}
```

- `conversation` 为会话元信息，`messages` 为当前筛选结果的分页消息集合。
- `messages.total` 是**筛选后的消息总数**，不一定等于 `conversation.messageCount`（整个会话的消息数量）。
- `parentMessageId`、`requestId`、`traceId` 可能为 `null`，取决于消息产生方式；不要假定所有消息都存在完整 Trace。
- 消息查询先验证会话所属应用是否位于 API Key 的工作空间及授权范围，再读取消息；不存在的会话 ID 返回 **400**，无权访问返回 **403**。

**两项查询接口的授权边界（重要）：**当前实现按 API Key 的**应用权限范围**隔离会话数据，**不按 `invokeSource`（企业名称）自动进行调用方级数据隔离**。若多个第三方共用一个授权应用，可能看到该应用下其他调用方产生的会话。上线对外开放历史内容前，应由业务方确认这种授权范围符合数据访问政策。

## 7. 失败处理和字段约定

- **认证失败**：通常 HTTP `401`，返回 `{"requestId":"req_xxx","code":401,"message":"Api key is invalid."}`。
- **应用查询失败**：使用 `requestId / code / message`（驼峰）；例如缺少筛选条件、无效分页参数。
- **Workflow 同步失败**：业务响应可返回 `status: "failed"`、`errorCode`、`errorMessage`；抛出的 HTTP 错误也可能直接使用 `statusCode / code / message`。
- **异步接口**：使用通用 `Result` 外层 `code / message / data`；外层请求标识字段若出现，名为 `request_id`；异步结果内部字段按本节示例使用下划线。
- **字段大小写**：Workflow 同步请求使用驼峰；但**当前异步接口尚未完全驼峰化**，必须按本文件给出的准确名称调用。
- **会话/消息查询失败**：同应用查询一样使用 `OpenApiResult` 的 `requestId / code / message / data`（驼峰）；请求参数不合法或会话不存在返回 HTTP `400`，无权访问返回 HTTP `403`，无效 API Key 返回 HTTP `401`。
- **会话/消息字段约定**：新接口请求使用 `camelCase`；请求分页为 `pageNum / pageSize`，响应分页为 `current / size / total / records`，不要和 Workflow 异步接口的 `snake_case` 混用。

> 本文示例中的 ID、文本、业务结果仅用于说明结构；实际取值以服务端返回和已发布应用配置为准。
