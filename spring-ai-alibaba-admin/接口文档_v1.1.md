# Spring AI Alibaba Admin 开放 API 文档 v1.1

## 1. 接入说明

- **Base URL**：`http(s)://{host}`（以实际部署地址为准）
- **认证**：所有 `/api/v1/**` 接口均须携带 `Authorization: Bearer <API_KEY>`
- **请求**：`Content-Type: application/json`；所有下列接口均为 `POST`
- **外部用户**：Workflow 请求可传 `userId`（第三方业务用户标识，**不超过 32 个字符**）；建议每次调用传入，便于会话和 Trace 关联。它**不是** `appId`，当前代码允许不传。
- **会话**：首次调用 `conversationId` 可留空；后续多轮交互传回上次得到的 ID。
- **发布版本**：调用应用时使用 `draft: false`；调用方无需传 `company_name`，该信息由 API Key 关联配置确定。

| 功能 | 路径 |
|---|---|
| 查询应用 | `/api/v1/apps` |
| Workflow 同步/流式调用 | `/api/v1/apps/workflow/completions` |
| Workflow 异步启动 | `/api/v1/apps/workflow/async-completions` |
| Workflow 异步查询 | `/api/v1/apps/workflow/async-results` |
| Workflow 停止 | `/api/v1/apps/workflow/stop-completions` |

## 2. 查询应用

`POST /api/v1/apps`

```json
{"type":"workflow","status":"published","pageNum":1,"pageSize":20}
```

| 请求字段 | 规则 |
|---|---|
| `appId` | 可选，精确匹配 |
| `name` | 可选，名称模糊匹配 |
| `type` | 建议填写 `workflow`，只查询工作流应用 |
| `status` | 可选，`draft` / `published` / `published_editing` |
| `pageNum` / `pageSize` | 默认 `1` / `20`；`pageSize` 最大 `100` |

**必须至少填写** `appId`、`name`、`type`、`status` 中的一项。

**返回示例（精简展示）：**

```json
{
  "requestId": "req_xxx",
  "code": 200,
  "message": "success",
  "data": {
    "pageNum": 1,
    "pageSize": 20,
    "total": 1,
    "records": [{
      "appId": "app_xxx",
      "name": "示例工作流",
      "type": "workflow",
      "status": "published",
      "publishedVersion": "3",
      "api": "/api/v1/apps/workflow/completions",
      "asyncApi": "/api/v1/apps/workflow/async-completions",
      "inputSchema": [
        {"key":"query","type":"String","required":false,"source":"sys"},
        {"key":"order_no","type":"String","required":true,"source":"user"}
      ],
      "requestJson": {"appId":"app_xxx","conversationId":"","stream":false,"draft":false,
        "inputParams":[
          {"key":"query","type":"String","source":"sys","value":"请输入用户问题"},
          {"key":"order_no","type":"String","source":"user","value":""}
        ]}
    }]
  }
}
```

- `inputSchema`：业务输入参数定义；`requestJson`：服务端生成的请求模板（上例仅展示结构）。**实际调用请以返回的完整 `requestJson` 和 `inputSchema` 为准。**
- 仅对有已发布版本的应用提供可用的调用配置；如果未找到已发布配置，可能返回 `schemaError`。
- 其他可能返回描述、图标、创建/修改时间、认证方式等字段，不影响基本联调。

## 3. Workflow 同步 / 流式调用

`POST /api/v1/apps/workflow/completions`

```json
{
  "appId": "app_xxx",
  "userId": "user_001",
  "conversationId": "",
  "stream": false,
  "draft": false,
  "inputParams": [
    {"key":"query","type":"String","source":"sys","value":"查询订单"},
    {"key":"order_no","type":"String","source":"user","value":"NO123"}
  ]
}
```

| 字段 | 说明 |
|---|---|
| `appId` | 必填，工作流应用 ID |
| `userId` | 可选，第三方用户 ID，最长 32 字符；建议传入 |
| `conversationId` | 可选，空值时服务端生成 |
| `stream` | 可选，默认 `false`；为 `true` 时使用 SSE |
| `draft` | 可选，外部使用已发布版本时传 `false` |
| `inputParams` | 工作流输入参数列表；按第 2 节返回的 `inputSchema` 填写 |

`inputParams[]` 包含 `key`（原始变量名）、`type`、`source`（`sys` 或 `user`）、`value`。通常 `query` 使用 `sys`，Start 节点自定义输入使用 `user`；**变量名保持原样**，不强制改成驼峰。

**非流式响应（业务对象）：**

```json
{
  "conversationId": "conv_xxx",
  "taskId": "task_xxx",
  "status": "completed",
  "content": "{\"result\":\"PASS\"}"
}
```

`status` 可能为 `in_progress`、`completed`、`failed`、`pause`；失败时可包含 `errorCode`、`errorMessage`。

**SSE**：将上述请求的 `stream` 改为 `true`，响应头为 `text/event-stream`。每条事件形如：

```text
data: {"conversationId":"conv_xxx","taskId":"task_xxx","status":"in_progress","content":"处理中"}

data: {"conversationId":"conv_xxx","taskId":"task_xxx","status":"completed","content":"完成"}
```

按 `status` 判断业务状态；不要依赖 OpenAI 式的 `[DONE]` 标记。

## 4. Workflow 异步调用

异步接口的部分字段**仍使用 `snake_case`**，与上述同步接口不同；以下名称严格对应当前代码。

### 4.1 启动

`POST /api/v1/apps/workflow/async-completions`

请求体使用第 3 节的 Workflow 请求格式（可不传 `stream`）。成功时：

```json
{
  "code": 200,
  "message": "success",
  "data": {"task_id":"task_xxx","conversation_id":"conv_xxx","request_id":"req_xxx"}
}
```

保存 `data.task_id`，用于异步查询或停止任务。

### 4.2 查询结果

`POST /api/v1/apps/workflow/async-results`

```json
{"task_id":"task_xxx"}
```

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "task_id": "task_xxx",
    "conversation_id": "conv_xxx",
    "task_status": "success",
    "task_exec_time": "1280ms",
    "outputs": [{"node_id":"node_end_1","node_name":"结束","node_type":"End","node_status":"success","content":"{\"result\":\"PASS\"}"}]
  }
}
```

- 查询请求和响应中的任务标识均为 **`task_id`**；不要写成 `taskId`。
- `outputs` 仅包含执行经过的 Output / End 节点；失败时还可能返回 `error_code`、`error_info`。

### 4.3 停止任务

`POST /api/v1/apps/workflow/stop-completions`

```json
{"task_id":"task_xxx"}
```

```json
{"code":200,"message":"success","data":true}
```

注意：停止请求明确使用 **`task_id`**（不是 `taskId`）；`data` 表示停止操作的布尔结果。

## 5. 失败处理和字段约定

- **认证失败**：通常 HTTP `401`，返回 `{"requestId":"req_xxx","code":401,"message":"Api key is invalid."}`。
- **应用查询失败**：使用 `requestId / code / message`（驼峰）；例如缺少筛选条件、无效分页参数。
- **Workflow 同步失败**：业务响应可返回 `status: "failed"`、`errorCode`、`errorMessage`；抛出的 HTTP 错误也可能直接使用 `statusCode / code / message`。
- **异步接口**：使用通用 `Result` 外层 `code / message / data`；外层请求标识字段若出现，名为 `request_id`；异步结果内部字段按本节示例使用下划线。
- **字段大小写**：Workflow 同步请求使用驼峰；但**当前异步接口尚未完全驼峰化**，必须按本文件给出的准确名称调用。

> 本文示例中的 ID、文本、业务结果仅用于说明结构；实际取值以服务端返回和已发布应用配置为准。
